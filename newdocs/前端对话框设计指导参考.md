## 0. 一句话设计语言

> **用户侧是受限的圆角气泡（右对齐、有背景、窄），Agent 侧是无容器的全宽叙述流；思考链和工具调用都是内联 / 全宽的可折叠灰字摘要行（折叠首行摘要、展开详情卡），运行时用扫光（shimmer）而非 spinner；无头像、无角色文字标签，时间戳和操作栏 hover 才出现，且 Agent 侧只在整轮结束后才挂 chrome。**

整套设计的核心是**刻意的不对称**：用户与 Agent 不用对称气泡，而用「气泡 vs 全宽纯文本」的几何差异来区分角色，从而省掉头像和角色文字标签。

## 1. 整体布局：用户气泡 / Agent 无气泡

内容列固定宽 `--dsh-chat-content-width: 748px`，消息流垂直排列，item 间距 16px。

### 1.1 用户消息 = 右对齐圆角气泡

- 圆角 22px 的气泡块，主题色背景填充（`--dsw-specific-bubble`）
- 最大宽度 `min(525px, 82%)`，在 748px 列内右对齐

- 气泡内 `/name`、`@name` 引用渲染成内联小药丸（`.refChip`，rgba 蓝底，6px 圆角）

## 2. 思考链（Think）的展示

思考链是 **inline 折叠行**，跟在 Agent 正文流里，按文档顺序夹在文本块之间——**不是独立面板**。

### 2.1 折叠态

- 一行灰字摘要 = 思考文本的**第一行**（流式时取**最新一行**），省略号截断
- 标题是字面量 "Think" + `IconThinkOutline14`，字重 400（不加粗）
- 2px 点分隔符接摘要；整行用三级灰色（`--dsw-alias-label-tertiary`）故意压暗

### 2.2 展开态

- 缩进 22px 的灰字正文（`.thinkBody`）
- 14px / 24px，`white-space: pre-wrap` + `word-break`
- 同样保持暗淡灰色调，视觉上从属于正文

### 2.3 运行态

- 行上有一道 300px 宽的光带从左往右扫过（shimmer 动画，2.6s 循环，`dsh-reasoning-row-sweep`）
- 带一个给屏幕阅读器用的 "running" 隐藏状态标签
- `prefers-reduced-motion` 时关闭扫光

### 2.4 折叠机制

用共享的 `DisclosureRow` 原语，整行 24px 可点（点击 / 回车 / 空格切换），图标 hover 时变成 chevron 预览。

**代码参考：**
- 思考行：`C:/dev/project/deepseek-harness/packages/client/ui-conversation/src/client/chat/ReasoningRow.tsx` / `ReasoningRow.module.css`（`latestLine()` / `firstLine()` 见 9-18 行）
- 折叠原语：`C:/dev/project/deepseek-harness/packages/client/ui-primitives/src/DisclosureRow.tsx`
- 嵌入点：`AssistantMarkdown.tsx` 68-70 行（`case 'reasoning'`）

> **描述口径：** 「思考链是内联可折叠行，折叠时显示首行灰字摘要，展开显示缩进灰字全文，运行时有左→右扫光动画；整体用三级灰压暗以区别于正文。」

## 3. 工具调用的展示

工具调用**不内联**在 Agent markdown 里（`AssistantMarkdown.tsx` 89-90 行的 `'tool-call'` case 故意是空操作），而是由 `ChatView` 分组成独立的全宽行，归 `ui-tool` 包管。

### 3.1 折叠态（恒为一行，24px）

布局：`[16px 图标] gap6 [标题 14/24] gap8 [2×2 点] gap8 [参数摘要 截断 FILL]`

- **图标**（按工具类型变体，14px outline）：
  - `search` → `IconSearchOutline16`
  - `read` → `IconBrowseOutline16`
  - `bash` → `IconApiOutline14`
  - `write` / `edit` → `IconEditOutline16`
  - `code` → `IconCodeOutline16`
  - 其他 → `IconSparkle16`
  - 错误 / 中断态换成 `StateDot`（红 = error，琥珀 = stopped）
- **标题**：工具名，字重 400
- **摘要**：参数派生的一行，省略号截断，灰字（`--dsw-alias-label-tertiary`）；单文件工具的摘要可 hover 下划线跳转（`.fileLink`）
- **错误行**：摘要直接用错误红（`--dsw-alias-state-error-primary`）显示失败首行
- **后缀**：`.summarySuffix`（如 todo 行的 `+n` 并行计数）不受截断影响

### 3.2 展开态（组件内 view state，默认折叠）

互斥的几种正文，都在标题行的 `.bodyWrap` 兄弟节点里（点击正文不会触发折叠）：

1. **IN/OUT 卡片**（`.ioCard`，最常见）
   - 圆角 12px 带边框，figma 1249:35657
   - 两段（IN 输入 / OUT 输出）各自独立滚动（最高 150px）
   - 左侧 sticky 标签 "IN" / "OUT"（`.ioLabel`）
   - 失败的 OUT 用错误红（`.ioText[data-error]`）
2. **CodeBlock**（shiki 高亮 TypeScript）——用于 `run_code`，滚动上限 260px
3. **专用卡**（按声明的 render intent 选择）：
   - `TerminalBlock`（终端输出 224px 上限）
   - `DiffBlock`（差异）
   - `ReadBlock`（带行号窗口）
   - `SearchBlock`（分组匹配 / 路径列表）
   - `WebBlock`（引用来源列表）

### 3.3 嵌套与生命周期

- 子调用在父调用下缩进，左侧一条细发丝竖线：`.subCalls { margin: 4px 0 2px 22px; padding-left: 8px; border-left: 1px solid var(--dsw-alias-border-l2); }`
- Cordis 生命周期工具（`data-tool^='cordis_'`）用共享的业务蓝强调色，字重 500
- hover 时露出 "Inspect" 胶囊按钮（`.inspectButton`，opacity 0→1），跳到独立的全高详情面

### 3.4 运行态

与思考链相同的扫光动画（`dsh-tool-row-sweep`，2.6s），加隐藏 AT 状态标签。

**代码参考：**
- 工具树：`C:/dev/project/deepseek-harness/packages/client/ui-tool/src/client/tool/ToolCallTree.tsx` / `ToolCallTree.module.css`（递归树 + 子调用嵌套）
- 工具行 + IN/OUT 卡：`C:/dev/project/deepseek-harness/packages/client/ui-tool/src/client/tool/components/ToolRow.tsx` / `ToolRow.module.css`
- 变体分类：`C:/dev/project/deepseek-harness/packages/client/ui-tool/src/client/tool/toolviews/GenericToolCard.tsx`（21 行起变体与图标映射）

> **描述口径：** 「工具调用是全宽单行可折叠行：折叠时显示 [类型图标 + 工具名 + 点分隔 + 灰字参数摘要]，展开后显示 IN/OUT 圆角卡片（输入 / 输出分栏独立滚动）或专用代码 / 终端 / 差异块；子调用缩进嵌套带左侧竖线；运行时扫光，hover 可跳详情面板。」

## 4. 流式 / 加载信号

分层信号，互不干扰：

- **Agent 正文流式**：`data-streaming` 属性 + MarkdownText 的光标 / 打字机行为；打断时淡显 "stopped"
- **轮级加载**：整轮运行时顶部一行 "Deep diving…" 蓝色 shimmer 文字（`dsh-turn-status-shimmer`，1.8s 线性循环），15 秒后旁边出现挂钟计时（`.turnStatusClock`，tabular-nums）。覆盖首 token 等待 / 工具执行 / 流式全过程，不会逐 step 闪烁
- **思考运行**：Think 行扫光（见 §2.3）
- **工具运行**：工具行扫光（见 §3.4）
- **重试激活**：重试文字 shimmer（`retry-shimmer`，1.6s）+ 倒计时

**代码参考：**
- 轮级加载：`C:/dev/project/deepseek-harness/packages/client/ui-conversation/src/client/chat/ChatView.tsx`（`TurnStatus`，107-140 行）/ `ChatView.module.css`（`.turnStatus`）

## 5. 时间戳 / 头像 / 角色标签

### 5.1 头像 —— 无

全仓库 client 包 grep `avatar` 零命中。无头像图、无首字母、无图标人像。

### 5.2 角色文字标签 —— 无

没有 "User" / "Assistant" 文字标签。角色区分纯粹靠气泡 vs 全宽几何差异。唯一的「角色味」文字是行标题 "Think"（思考）和工具名（工具行）。

### 5.3 时间戳与操作栏

- **时钟 hover 才显示**（hover-capable 设备）：默认 `opacity: 0`，hover / focus-within → `opacity: 1`；非 hover 设备常显
- **时钟侧别按角色不同**：
  - 用户：时钟在图标**前**（`clock="start"`，`.timeStart`，右 padding 12）
  - Agent：时钟在图标**后**（`clock="end"`，`.timeEnd`，左 padding 12），并附带运行指标，`·` 分隔：`· Ran for 15s`、`· TTFT 1.2s`、`· 34 tok/s`
  - 时钟文字 14px / 24px，`--dsw-alias-label-tertiary`，tabular-nums
- **操作按钮**：28px 圆形，透明，三级灰；hover → `--dsw-alias-interactive-bg-hover`
  - 复制（`IconCopyOutline16` → 成功后换成 `IconCheckOutline16` 1 秒）
  - 分支 / Fork（`IconBranchOutline16`）—— 仅完成轮尾 / Agent 回答有；非 transcript 尾节点禁用（`data-unavailable`，opacity 0.4）

### 5.4 操作栏挂载位置

- **用户**：`MessageIconActions` 坐在气泡**下方**（`MessageItem.tsx` `UserStyleBubble`，`clock="start"`，`time={data.time}`）
- **Agent**：操作栏在独立的 **turn-tail 节点**里，位于完成轮底部（不在流式 partial 上）。组合 `MessageIconActions`（`clock="end"`）+ `runMs` + `ttftMs` + `tokensPerSecond` + 分支回调（`forkAt`）。轮运行中 / 轮内叙述不挂任何 chrome，直到轮关闭才出现

- Agent 轮尾：`C:/dev/project/deepseek-harness/packages/client/ui-conversation/src/client/chat/TurnTailNodeView.tsx`

## 9. 迁移到 sc2Agent ChatDock 的要点

本仓库 `web/src/shell/ChatDock.tsx` 当前是对话面板入口。若复用 deepseek-harness 的设计语言，可参考：

1. **不对称布局**：用户侧右对齐气泡 + Agent 侧全宽纯文本，省掉头像与角色标签——直接降低视觉噪音
2. **思考链 / 工具调用统一为可折叠摘要行**：折叠首行摘要、展开详情卡，运行时扫光而非 spinner——与 sc2Agent 的 agent steps 可视化（steps 可视化已是 P3 切片方向）天然契合
3. **轮级加载 vs 逐 step 加载**：整轮一个 "Deep diving…" 信号 + 挂钟计时，不逐 step 闪烁——sc2Agent 执行轮多 step，这点尤其值得借
4. **Agent chrome 延迟挂载**：流式过程中正文干净，轮结束才挂操作栏 + 运行指标——避免半成品 chrome 干扰
5. **时间戳 / 操作栏 hover 才显示**：降低常驻噪音
6. **设计 Token 分层**：语义别名（`label-tertiary` 等）+ 品牌静态色，CSS Modules 隔离

> 注意：deepseek-harness 用 pnpm monorepo + 独立 `ui-conversation` / `ui-tool` / `ui-primitives` 包；sc2Agent 前端是单 Vite 工程，迁移时按本仓库现有目录结构（`web/src/...`）组织，不必照搬分包。
