# ADR-0007 browser：实时地图与实时生产投影

- 状态：已废弃，由 ADR-0022 替代
- 范围：`browser` 模块 V1 功能边界（UI 最后实现，但接口现在固定）

## 背景

旧 browser 的问题：三栏布局堆功能，地图编辑、规划器、live 观察、聊天混在一起，操作手感差，且前端重复了部分游戏规则。

重构原则：browser 只做展示与交互，不承载游戏规则。V1 必须支持两条 live 视图，且与离线编辑清晰分离。

## 决定

### 1. 实时地图规划视图

```text
live GameState / events
        ↓
TacticalMap.live_view()
        ↓
地图画布
```

- 地形层只加载一次。
- 动态层持续更新：建筑、挂件、建造进度、我方单位、敌方单位或聚类、威胁区、矿区、look 区域。
- 三种显示状态：
  - `编辑`：用户自己的离线规划；
  - `实时`：当前真实对局；
  - `叠加`：用户规划半透明叠在实时地图上，用于对比“想放这里 vs 实际在哪里”。
- 用户规划与 live 数据分离，live 刷新不得覆盖用户正在编辑的草稿。

### 2. 实时生产规划视图

```text
最新 GameState + 当前 FlowSpec
        ↓
Planner.simulate(state, projection_spec, horizon=N)
        ↓
ProjectionMonitor
        ↓
/ \
UI 预测曲线      agent/警报预警
```

- 每 3–5 秒用最新完整 GameState 重算未来 60–120 秒的生产投影。
- UI 展示：
  - 实际资源曲线 vs 预测资源曲线；
  - 计划 Gantt vs 实际进度；
  - 下一批将完成的建筑/单位；
  - 预测警告：卡人口、浮矿/浮气、产线空闲、前置缺失、计划漂移。
- `ProjectionMonitor` 同时向前端和 agent/警报供数，禁止前端另算一套警报。

### 3. 离线编辑与 live 投影分离

- 离线编辑的 plan 是草稿。
- 局内当前 FlowSpec 是现实。
- live 生产规划默认展示当前 FlowSpec 的投影。
- 用户可在草稿 plan 上选择“对比当前 flow”，并排展示两个未来。
- 草稿不会因 live 数据刷新而被直接当成现实或覆盖。

### 4. 布局与交互方向

V1 按任务组织，不沿用旧三栏堆叠：

```text
离线规划 / 对局驾驶舱 / 对话 / 复盘
```

- 每个任务页只展示该任务需要的数据与操作。
- 地图画布、生产规划、聊天、复盘可复用组件，但页面上下文清晰。
- 聊天与美学优化属于最后阶段，不在核心模块重构期阻塞。

### 5. 接口边界

browser 只消费后端模块提供的结构化数据：

- 地图实时数据来自 `tactical_map`。
- 生产预测来自 `planner`。
- 约束错误来自 `constraint`。
- 模块/flow 数据来自 `flow` 模块库与 FlowSpec API。
- browser 不实现任何游戏规则，不重复 canPlace / validate / simulate。

## 反例（明确禁止）

- 在 TS 中复制一份 canPlace 或约束规则。
- live 轮询直接覆盖用户正在编辑的地图草稿。
- 前端自己根据资源数字写一套“卡人口警报”。
- 将离线草稿静默当作 live 当前 flow 提交。

## 验收标准

1. live 地图视图与离线地图编辑可同时打开，互不覆盖。
2. 实时生产投影每 3–5 秒更新，且与实际推进趋势一致。
3. 卡人口/浮矿/浮气预警同时出现在 UI 与 agent 侧，来源为同一 ProjectionMonitor。
4. 用户可对比“草稿 plan”与“当前 flow”两个未来。
5. browser 源码中不存在游戏规则实现。
