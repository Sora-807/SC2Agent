# ADR-0008 地图层级、区域划分与区域化观察

- 状态：已确认草案
- 范围：地图数据组织、红蓝方适配、agent 观察方式

## 背景

- 旧项目让 agent 频繁使用 `look` 逐格扫描地图，reasoning 大量消耗在复述格点文本上。
- 实际对局中，agent 更需要总结性信息：资源、关键建筑、部队、生产序列、预测，再按区域展开建筑与兵群。
- 地图规划需要区分红蓝方开局，且需要多层级数据互不覆盖。
- 坐标约定过去不够明确，格点文本中 y/x 反直觉。

## 决定

### 1. 坐标约定

统一采用：

```text
(0,0) 在左下角
x 向右递增
y 向上递增
```

- game、tactical_map、constraint、planner、browser 全项目统一。
- SC2 世界坐标或图像像素坐标的转换只发生在 driver / browser 薄适配层。
- 该约定同样写入 ADR-0002，作为 game 层基础规则。

### 2. 地图数据层级

地图数据按层组织，而不是把红蓝方复制成两份完整地图：

```text
L0 地图底图（共享）
    地形、资源、基础路径、全图格点

L1 地图静态配置（每张地图一份）
    地图 ID、尺寸、出生点、矿区、区域划分、红蓝方方向定义

L2 红/蓝方视图（派生，不复制地形）
    从 L0/L1 派生：哪一侧是“我方主矿/二矿/三矿”，区域名称随阵营变化

L3 默认规划模板（新建规划时复制）
    基本开局信息 + 全量地形引用 + 区域划分 + 默认常用标注区

L4 用户地图规划（current）
    用户自己编辑的 markers、建筑规划、预留区

L5 agent 草稿地图（pending）
    agent 提交的规划草稿，审批后写入 L4

L6 live 实时层
    当前真实对局的建筑、单位、威胁、进度、look 高亮
    以及 GameState.map_layers：creep / power / addon_attachment / visibility 等
```

规则：

- L0/L1 是共享只读数据；红蓝方差异通过 L2 派生，不复制全图。
- 新建空白规划时，从 L3 模板复制，而不是从空文件开始。
- L4 用户规划与 L5 agent 草稿分开存储；L5 审批通过后才覆盖 L4。
- L6 live 数据只在 live 视图内作为叠加层显示，不得写入或覆盖 L4/L5。
- 地形数据只在 L0 保存一份，任何层不得再次复制全量地形。
- L0/L1 来源管线：离线工具从 burnysc2 地图数据提取地形/出生点/扩张点；区域自动生成基于出生点与扩张点聚类；人工精修覆盖自动结果；L0/L1 版本化存储，不硬编码在代码中。

### 3. 区域划分

- 每张地图在 L1 中定义区域：主矿、二矿、三矿、中央、分路等。
- 红蓝双方各自有一套区域视图：同一个坐标区域，对蓝方可能是“我方主矿”，对红方则是“敌方主矿”。
- V1 先用出生点 + 扩张点自动生成基础区域；支持每张地图的人工精修配置覆盖自动结果。
- 区域定义属于数据，不允许 agent 或 flow 在运行期把“哪里是主矿”写死在提示词里。
- `tactical_map` 提供按区域查询与汇总的接口，agent、browser、alerts 共用。

### 4. 区域化观察（替代逐格 look）

live 观察的主格式改为结构化区域摘要：

```text
### 当前状态
#### 资源状态
- 晶体矿：xxx
- 瓦斯：xxx
- 补给：used/cap

#### 关键建筑数量
| 建筑 | 总数 | 科技挂件 | 双倍挂件 |
|---|---|---|---|

#### 已有全部部队
| 兵种 | 数目 |
|---|---|

#### 生产序列
| 兵种 | 正在训练 | 待训练队列 |
|---|---|---|

### 30 秒后预估
- 资源、补给、即将完成单位/建筑、预警
- 该段必须带 `projection_seq` 与 `projection_time`；投影刷新频率低于观察时，明确标注“预测生成于 T，基于 seq N”。

## 区域信息

### 我方主矿（x1,y1；x2,y2）
#### 建筑信息
- 兵营：坐标、血量、进度、挂件
#### 兵种信息
- 名称（数量）：坐标、血量百分比

### 我方二矿（x1,y1；x2,y2）
...
```

- 该摘要由 `tactical_map` 与 `planner` 的 30 秒投影共同生成，数据源唯一。
- agent 每次触发都拿到完整区域摘要，不再需要为了了解全局而反复 look。
- `look` 降级为按需查询具体小区域/具体坐标的补充工具，主要用于离线规划摆位和在线少量核对。

### 5. 中文展示

区域名称、建筑/兵种名称全部通过 game 数据目录的中文名称渲染；agent 观察输出同样使用中文。内部数据仍为稳定 ID。

## 反例（明确禁止）

- 把红蓝方地形复制成两份完整地图数据。
- 在 agent 提示词中为每张地图写死区域坐标。
- live 刷新覆盖用户正在编辑的 L4 规划。
- 观察输出只给逐格文本，没有区域汇总。
- 区域划分逻辑散落在 browser 和 agent 两处。

## 验收标准

1. 任何坐标从 driver 进入 game 后都符合左下角原点约定。
2. 同一张地图的蓝方/红方视图可从共享底图派生，且主矿/二矿名称正确互换。
3. 新建空白规划会复制默认模板：开局信息、地形引用、区域划分。
4. 用户规划、agent 草稿、live 数据互不覆盖。
5. agent 标准观察包含资源、关键建筑、部队、生产序列、30 秒预估和分区域信息。
6. look 不用于获取全局态势，仅用于局部细节查询。
