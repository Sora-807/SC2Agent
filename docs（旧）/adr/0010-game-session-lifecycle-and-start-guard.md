# ADR-0010 游戏会话生命周期与重复开启防护

- 状态：已确认草案
- 范围：游戏进程/SC2 会话的启动、停止、崩溃恢复、重复点击与 agent 工具并发防护

## 背景

多次开启游戏的情况已经实际发生过：

- 用户多次点击前端“开始游戏”。
- 用户点击开启后，agent 的 `start_game` 工具又尝试开启一次。
- 旧进程记录失效、SC2.exe 已存在但未被识别，导致重复启动。
- 停止时也可能重复执行，造成误杀或孤儿进程。

## 决定

### 1. 唯一会话控制器

所有“开始/停止游戏”请求必须经过唯一的 `GameSessionController`：

```text
browser 按钮 ─┐
API 请求 ─────┼→ GameSessionController → driver / SC2 进程
agent 工具 ───┘
```

- 禁止 agent 工具、API、前端各自直接 spawn 游戏进程。
- 控制器是启动/停止的唯一路径。

### 2. 状态机

```text
stopped → starting → running
                 ↘ crashed
running → stopping → stopped
starting → stopped   # 启动失败
running  → crashed   # watchdog 发现进程死亡
```

- 所有状态转换必须原子完成。
- `start` 在 `starting` 或 `running` 时是幂等操作，不产生第二个进程。
- `stop` 在 `stopped` 时是幂等操作，不报错、不重复杀进程。

### 3. 启动防护顺序

每次 start 请求依次经过以下防护：

1. **会话锁**：获取带 owner 和心跳的会话锁；锁已被持有且有效则直接返回当前会话。
2. **进程记录检查**：读取 game proc 记录，检查 pid 是否真实存活；陈旧记录视为无效。
3. **SC2 进程检查**：不能只按进程名判断。必须结合启动路径、命令行参数、父进程/启动器标记、本项目写入的 session 标记，识别“本项目启动的那个实例”；识别到的实例存在时不得重复启动。其他无关 SC2 进程不误判。
4. **请求去重**：start 请求带 `request_id`；相同 request_id 的重复请求返回同一个会话结果。
5. **通过后创建会话**：写入 proc 记录、会话 id、启动时间、驱动版本、FlowSpec 哈希。

### 4. 重复请求的行为

- 状态为 `starting`：返回“正在启动中”，不创建新进程。
- 状态为 `running`：返回当前会话信息。
- 检测到游戏已在运行：返回冲突原因，前端与 agent 都不得降级为“忽略并继续”。
- 所有重复请求都记录日志，便于定位是前端连点还是 agent 误调。

### 5. 停止防护

- `stop` 由控制器统一执行：先请求正常退出，超时后强制结束，最后兜底清理孤儿进程。
- 停止完成后清理会话锁与 proc 记录。
- 重复 stop 请求返回“已停止/停止中”，不重复 kill。

### 6. 崩溃与看门狗

- driver 定期写心跳；控制器或看门狗发现心跳超时或进程死亡后，将会话标记为 `crashed`。
- `crashed` 状态不允许自动无脑重启；只有用户显式再次 start 才重新创建会话。
- 崩溃前的 FlowSpec、版本树、计划数据必须保留。

### 7. 前端约束

- 开始按钮在 `starting / running` 状态禁用。
- 按钮状态以后端控制器状态为准，不以前端本地点击状态为准。
- 页面刷新后通过会话状态接口恢复按钮状态。

## 反例（明确禁止）

- agent `start_game` 工具内部自己 spawn 游戏进程。
- 前端按钮只做本地 disabled，不校验后端状态。
- 看到旧 proc 记录时直接认为游戏不在运行。
- start 过程中再次 start 时创建第二个 driver。
- stop 请求被重复执行导致误杀其他进程。

## 验收标准

1. 并发触发 3 次 start（模拟多次点击 + agent 工具），最终只存在一个游戏会话。
2. 相同 `request_id` 的重复 start 返回同一会话结果。
3. 本项目启动的 SC2 实例已在运行时，start 返回明确冲突；其他无关 SC2 进程不会被误判。
4. 陈旧 pid 记录可被正确识别并清理。
5. 重复 stop 不产生错误，不误杀无关进程。
6. driver 崩溃后状态为 crashed，FlowSpec 与计划数据仍保留，且不会自动拉起第二个游戏。
