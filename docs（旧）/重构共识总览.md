# sc2_agent_next 重构共识总览

> 本文件是当前所有讨论的最终总结。ADR 细节在 `docs/adr/`。
> 状态：已确认草案；尚未实现，确认前不写正式代码。

## 1. 顶层架构

```text
game
 ↑
tactical_map / mechanics
 ↑
constraint
 ↑
planner
 ↑
flow
 ↑
runtime
 ↑
agent / api / browser

driver 只依赖 game，实现 GamePort；runtime 通过 GamePort 接入
```

- 新代码不 import 旧项目。
- 旧 workspace 数据（TL 坐标 plan、旧 flow 等）V1 不做自动迁移；需要时另做一次性迁移工具，不允许在核心代码里兼容旧格式。
- 模块内部实现可自由改；跨模块概念只做增量加法。
- 所有模块有 contract tests 和依赖检查。

## 2. 当前已经形成的核心共识

### 2.1 game

- 数据在 JSON：`terran.json / protoss.json / zerg.json`。
- 稳定类型 ID，如 `terran/marine`；SC2 枚举名只是 driver 映射字段。
- 下游通过注册表按 role/capability/tags 查询，不写死具体单位。
- 每个类型有 `display_name_zh / description_zh / aliases_zh`。
- GameState 不包含任何种族专属固定字段；planner 的初始输入必须是完整 GameState。
- `GameState.map_layers` 统一承载地图二维属性层：creep / power / addon_attachment / visibility 等。
- 菌毯等动态层由 driver 从 SC2 直接读取；power/addon 等确定性层由 `mechanics.LayerComputer` 计算；在线由 runtime.world 补齐，离线由导入工具补齐；tactical_map 查询。
- 全项目坐标：左下角 (0,0)，x 向右，y 向上；建筑格点整数，单位位置浮点世界坐标。
- 建筑 placement 用 TL+BR+size；单位距离判定用浮点世界距离。
- game 零 burnysc2 依赖。

### 2.2 planner

- 只做经济/生产确定性投影，不模拟战斗。
- 输入：完整 GameState + production projection spec + mechanics + horizon。
- 输出：可查询 Projection，按绝对游戏时间查询，必须显式 `after` 锚点。
- 缺字段报 `INCOMPLETE_INITIAL_STATE`，不猜测。
- 任意时刻 live GameState 都可作为起点。

### 2.3 flow / 模块体系

- 分层：模块库 → FlowAssembly（`docs/spec/005`）→ FlowIR。
- production 模块：声明式 policies，可投影 full。
- 所有 build 操作必须携带 placement（精确坐标/区域/预留区/placement policy），缺 placement 编译失败。
- combat Strategy：`group_slots + 步骤图 + step`，见 `docs/spec/002`。
- FlowAssembly 结构：
  - `production_sequence`：生产阶段按顺序执行；
  - `groups`：兵权租约，自动补兵；
  - `strategy_instances`：group ↔ strategy 绑定。
  - **V1 无 signals / combat_overlays / triggers**；生产产出进入 free 池，由 Group 自动补兵，Strategy 首步等待 `group_count`。
- live 只允许 group 操作、attach/switch/detach/pause/resume、改参数；战斗中禁止创建新 Strategy/模块。
- FlowAssembly 持久化 JSON，编辑走装配层 patch 操作（见 spec-005）。
- 提交前强制 validate + compile +（含生产变更时）simulate。

### 2.4 combat 模块最终形态

```text
Strategy = 单层步骤图（允许有界环）
  formup / advance / combat / retreat / hold

step = 每帧求值的 if/elif/else 扁平分支表
step 退出 = ExitRecord(kind, reason, payload, seq)
边按退出原因路由
```

- 游戏循环就是循环；step 内不写 while，不允许 if 嵌套。
- Strategy 步骤图允许有界环；每个环必须有非环出口和转移上限。
- 回到某 step = 新 entry，`step_entry_count += 1`。
- 分支条件只使用 `docs/spec/003` 的原子目录。
- 退出原因目录见 `docs/spec/004`。
- 旧的“策略层 + 尝试层”两层模型已废弃，见 ADR-0028。

### 2.5 原子层

四类底层对象：

1. SpatialTool：区域中心、集群中心、最近单位、距离。
2. SelectorAtom：只用于 Group 创建/补兵/拆分。
3. PredicateAtom：group_count、arrived、engaged 等，目录见 spec-003。
4. ActionAtom：move、attack_move、hold、follow、load/unload 等。

单位分配（Group 模型）：

- Group 是兵权租约；Strategy 只消费 group_slots。
- `pool_key + share + priority` 参与 TaskAllocator 仲裁。
- 两阶段算法：先保底 `min`，再按 share 追 `target/max`（spec-006）。
- 无 share 重叠 → 警告 + 均分；share 总和 >100 → 离线拒绝，运行时归一化 + 告警。
- 单位池：free / user_leased / flow_leased；用户 > flow。
- 已 lease 单位不参与重分配；补兵只从 free 池取。

### 2.6 状态与热切换

- GameState 是世界真相；生产模块实例状态与 combat Strategy 状态存在 FlowRuntimeStateStore。
- 生产模块实例 key = `(game_session_id, flow_id, instance_id)`。
- combat 状态以 Strategy 绑定实例为准：active_step、step_entry_count、variables、locals。
- 提交新 FlowAssembly 按 diff 保留状态：
  - hot 参数：保留；
  - 结构参数：只重置该实例（生产）或运行期拒绝（combat）；
  - 改 order / attach / switch / detach：按 spec-005 迁移；
  - 删除：取消并释放；
  - 新增：从初始状态开始。
- 终态不自动重跑；生产实例显式 `retrigger` 产生新 attempt。
- Strategy 步骤图环体现为 step_entry_count 递增。

### 2.7 agent V1

- live 默认 `no_think + intent router`。
- router 实现 = `FastRuleTable + NoThinkLLMParser + PatchValidator`。
- 非思考 LLM 单次输出结构化 JSON patch，无推理链、无工具、无自由文本。
- 不支持的指令明确拒绝，不硬猜。
- 离线模式负责创建/测试/入库模块。
- `retrigger_instance` 进入工具面，不改 FlowSpec，不重新 validate/simulate，但写 flow_event。

### 2.8 观察、区域与地图

- 区域化观察是主格式：资源/建筑/部队/生产序列/30 秒投影 + 分区域信息。
- look 降级为局部查询。
- ObservationPacket 带 seq，新观察替换旧观察，旧观察进 trace。
- 地图层：底图 → 红蓝方派生视图 → 默认模板 → 用户规划 → agent 草稿 → live。
- 红蓝方不复制全量地形。

### 2.9 浏览器

- **地图规划 + 生产规划是离线 Flow 生产工具**：玩家与 agent 商量区域、生产阶段、Group 和 Strategy，最终生成 FlowAssembly。
- **live 是独立驾驶舱**：实时地图、生产投影监视器、策略图状态、区域观察、警报、对话；不与离线画板叠加。
- live 地图支持图层开关显示菌毯、能量场、挂件预留位、视野等 map_layers。
- 生产投影只基于 production_sequence + 最新 GameState，不模拟 combat 策略环。
- 运行时实例泳道：生产泳道 + 战斗策略图显示。
- UI 不实现游戏规则。
- 离线草稿与 live 数据分离。
- 第一层级：实时游戏 / 复盘 / 规划；内部选项卡见 ADR-0023。
- 时间线采用“快照 + 日志回放”；V1 支持跳转快照/事件点，不承诺任意帧平滑回放。
- Flow 历史采用事件溯源：workspace 初始快照 + flow_events + runtime snapshots + 版本树，见 ADR-0024。

### 2.10 游戏会话

- 唯一 GameSessionController，归属 runtime/session。
- 状态机：stopped/starting/running/stopping/crashed。
- start 幂等、request_id 去重、SC2 进程检测、陈旧 pid 清理。
- SC2 进程识别不能只按进程名，需结合启动路径、命令行、父进程/启动器、本项目 session 标记。
- 崩溃不自动重启，保留计划数据。

### 2.11 runtime 协调层

- 位置：flow 之上、agent/api/browser 之下，见 ADR-0025。
- 子域：session / world / allocation / execution / projection / history / facade。
- flow 只依赖端口；runtime 实现端口；driver 实现 GamePort。
- 恢复 = 骨架状态恢复 + 最新 GameState 重校准派生进度。
- 节拍：观察/地图/UI 1 秒，投影 3 秒，快照 5 秒，关键事件即时。

### 2.12 voice 范围

- V1 不实现语音。
- 语音是 V1.5 通道：STT 输出文本后，与文本消息走同一个 IntentRouter；TTS 只负责朗读回复。
- 不在 V1 引入独立的语音决策路径。

## 4. 下一步还需要思考/确认

### 4.1 已确认 / 仍待确认

已确认：

1. ADR-0028 的 Flow 语义模型 v0.2（spec-001~006）为最终模型：Group / Strategy / Step / FlowAssembly。
2. 新增 runtime 协调层，见 ADR-0025。
3. router = FastRuleTable + NoThinkLLMParser + PatchValidator。
4. `GameState.map_layers` 方案：driver 填充，tactical_map 查询。
5. 新文件夹名 `sc2_agent_next`。
6. V1 无 signals；生产产出由 Group 自动补兵，Strategy 首步等待 group_count。

已定：

1. V1 先只做 Terran 完整实现，Protoss/Zerg 用 JSON schema + 测试夹具锁接口。

仍待确认：

1. production manifest 的正式字段与 placement policy 目录。
2. strategy authoring 工具形态（JSON 直写还是可视化编辑器先行）。

以 ADR-0028 和 spec-001~006 为基线，接着做：

1. **production manifest schema**：production 模块字段与 placement 规则。
2. **strategy authoring 工具与测试门禁**：基于 spec-002/003 定义场景测试与入库标准。
3. **flow_events 与 runtime snapshot schema**：落实 ADR-0024 的事件格式和快照格式（注意恢复权威源修正）。
4. **V1 Terran 策略/模块清单**：至少含速开二矿、两船兵生产、两船兵推进、守斜坡/守二矿、简单包抄。
5. **GameState 完整性清单**：哪些字段缺失会触发 planner 报错。
7. **L0/L1 地图数据来源与生成管线**：burnysc2 提取、区域自动生成、人工精修、版本化。

## 5. 当前红线（任何时候不得回退）

- live 中不允许创建/编辑模块与 Strategy。
- 战斗中不允许让 agent 现场写自由 DSL 或 Python。
- 任何 flow 提交必须 validate + compile；含生产变更时还要 simulate。
- 用户操作优先于 flow。
- 配置错误可以降级运行并告警，但不能打崩游戏。
- 旧观察不能作为当前行动依据。
- 不模拟战斗结果。
