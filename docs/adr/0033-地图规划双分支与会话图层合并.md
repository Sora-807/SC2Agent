# ADR-0033：地图规划双分支 + 会话图层合并 + 默认热切

日期：2026-08-24 ｜ 状态：已采纳（PLAN-V2 批 2，执行记录见 WORKLOG §0.60） ｜ 影响：
view/map_plans、tactical_map/{merge(新),base,mine_areas(新),region_view}、
production/placement、api/{session,routes/session,routes/commands,routes/map_plans}、
tools/run_session、agent/readonly、前端 planning 面；**契约零改动**（内容变化不加字段）

## 背景

两个旧模型各有结构性问题：

1. **一规划 = 一出生点**（P2 以来：`spawn: bl|tr` + 平铺槽位，预设四件
   default-bl/tr + layout-bl/tr）。用户原始设计从来是「左出生点和右出生点是
   **一份**地图规划的两种不同结构」——单侧文件把同一布局意图拆成两份，复制/
   同步都要人工做两遍。
2. **会话只装一份规划**（`load_map_plan(path)` 单文件 → instantiate），
   `resolve_placement_refs` 在 REST 层把跨规划引用（`规划名/点位名`）整个拒掉：
   引用只能钉在"会话当前装的那份"上，队列里想引用另一份布局的槽位做不到。

## 决定

**一份规划双分支；会话图层合并；默认可热切。**

1. **双分支文件形态**：`spawns: {bl: {origin, anchor, build_slots, pos_marks},
   tr: {…}}` 一份两结构；单分支旧格式（`spawn:` + 平铺）继续可读（load_map_plan
   兼容包装），但预设/新建全是双分支。预设从四件收敛为两件（`default` 空白 /
   `layout` 出厂校准），旧锁定件 init 时退役。保存（hunks 与全量 doc）作用于
   **指定分支**；全量 doc 校验对每个提供的分支各跑几何/预留/简写。

2. **会话图层 = 三种解析**（`tactical_map/merge.merged_layer`）：
   - **默认规划 = 裸名**：其槽位构成 home 区的 build_slots 名单 ——
     `placement: null` 自动放置（ADR-0027 修订）按声明序只消费默认份；
   - **全部规划 = `规划id/名字` 命名空间键**（含默认自己）：显式引用钉在规划上，
     不随默认热切漂移；合并时槽位对象的名字也带前缀（map_static 按 name 渲染）；
   - **预设固定建造点 = 全局裸名**（reserved_marks，与装载哪份规划无关）。
   所有规划按**同一个出生端**（spawn_key）实例化到同一个实际 CC。默认规划
   不存在 → 出厂模板兜底（默认身份如实记 None）。

3. **默认热切**：`POST /api/session/map-plan?id=`，帧边界重建合并图层 →
   runtime/keeper/engine/producer 四方换 region_layer 引用 → 重发 static/map
   （抄 swap_strategy 的 pending 模式；live 走控制文件通道）。`resolve_placement_refs`
   及其「跨规划拒绝」逻辑删除 —— 引用直通，不存在的标记执行期 dropped（D6）。

4. **null = auto**（批 1 已记 ADR-0027 修订，此处落地）：`placement.py` 的 null
   拒绝改为默认 `in_region("home")`；无位可放 = skip(placement_collision)。
   仿真侧槽位近似模型归批 3。

5. **矿区划分进基础数据**（D4）：`tactical_map/data/ladder_map/mine_areas.yaml`
   六矿区（name/side/bbox），**草案坐标待真机校准**（文件头标注）；批 4 observe
   v2 以此表为分区基准，校准只改数据文件。

## 被取代/落地的旧决策

- P2「规划 = 某地图 × 某方的一种布局」→ 一份双分支（用户原始设计回归）。
- I8 的「限定引用在 REST 层映射 + 跨规划拒绝」→ 命名空间键直通（合并层解析）。
- ADR-0027 的「null 的 build 不通过」反例 → 修订节（2026-08-24）正式落掉。

## 权衡与后果

- 命名空间键让 static/map 的 build_slots 变多（每规划一份裸名 + N 份前缀名）：
  形状不变无 REV；前端画布按 name 渲染即得。
- 旧单分支文件继续可读但**新建一律双分支**；用户存量单分支副本不强制迁移。
- maps 只读区（agent 文件面）对双分支默认渲染 bl 侧（文件路径没有分支位），
  说明行标注；对局实时图层仍走 observe（按实际出生端实例化）。
- agent 切地图的工具面等用户设计文档（REST 已先行）；前端红蓝 = 同一规划的
  分支页签（spawn 从"规划过滤键"变"视图"），驾驶/复盘画布用的会话帧本身已按
  实际出生端实例化，无需额外处理。
