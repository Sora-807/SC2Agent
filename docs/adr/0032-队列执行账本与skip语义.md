# ADR-0032：队列执行账本与 skip 语义（取代「队首冻结」拍板）

日期：2026-08-24 ｜ 状态：已采纳（PLAN-V2 批 1，执行记录见 WORKLOG §0.59） ｜ 影响：
game/production、production/{runtime,semantics,flights}、view/{schema,adapt,proposals,alerts,observe}、
api/commands、契约 rev 18

## 背景

生产队列从 P0 以来是「队首门控 + 执行即出队」：队首不可行整条队列冻结（S11），
执行过的项从 `q.items` 里消失。真机暴露出两个结构性问题：

1. **队首冻结把 skip 类失败放大成全队瘫痪**。兵营被拆后排在后面的补给站/工兵
   全部停摆（真机两枪兵卡死事故的同族根因）；放置位耗尽同理。
2. **下标引用天然不稳**。命令面（insert/remove/reorder）和提案 hunk 都用
   `index`，但已执行项出队后下标持续漂移，agent 在「看到帧 → 提提案」的间隙里
   队列一动，index 就指错项。提案的 anchor 新鲜度门（§6 P5）只保证世界没大变，
   不保证下标没漂。

同时 planner 仿真与 live runtime 各写一套可行性判据（`_feasible` vs
`check_build/check_train` + `_shortage`），语义漂移已经发生过（投影说能造、
真机卡住）。

## 决定

**队列 = 执行账本；执行语义 = 单点分类器；失败 = 标记跳过继续。**

1. **账本**（`game/production.QueueItem` + `production/runtime`）：
   - 每项带 `uid`（runtime 入队时分配，per-queue 递增 `q01…`，clear 不重置、
     重排/插入不变）—— 命令与提案的引用锚点从下标换成 uid；
   - `status` 四值闭集 `pending / in_progress / completed / skipped`（D8：
     live 与仿真同枚举；不要 not_reached —— 仿真里 horizon 没碰到的就是 pending）；
   - **已执行项保留在队列里**不再摘除；BUILD 完成 = flight 确认实体
     `build_progress>=1`（§0.53），TRAIN 完成 = `_trainings` 账本淘汰（G3）；
   - 帧反解回灌（live `queue_items` → hunk → submit）往返 uid/status ——
     丢 status 会让已完成项被重跑。

2. **分类器**（`production/semantics.classify(item, catalog, view)`，纯函数）：
   `ready | pending(中文原因) | skip(闭集 reason)`。一套语义三个消费方
   （runtime._drain 已接；planner 仿真与 simulate 健康检查批 3 接入）：
   - pending = 矿/气/人口未齐、前置在途或在队列、产出建筑在途/在队列、
     **训练槽满 production_capacity**（槽满是瞬态，归等待；超 60s 警报层升 warn）；
   - skip = `prereq_missing`（不在场、不在途、也不在队列）｜
     `placement_collision`（无可用槽位/候选耗尽/footprint 冲突）；
   - 语法/作者错误（catalog 不认、标记不存在、未知 op）**不经 classify**，
     runtime 直接 dropped 摘除（D6 分工）。

3. **drain 语义**（skip-and-continue）：skip → 标记后**继续下一项**（不级联）；
   pending → 队首等待，**不越序执行后续项**（顺序语义保留 —— 乱序执行破坏
   build order 且跨帧累计超支）。队首冻结只对 pending 保留。

4. **命令面换 uid**：`insert(before_uid)` / `remove(uid)` / `reorder(order=uid
   排列)`；提案 hunk 同步（insert 用 before_uid、delete/modify 用 uid）。
   同仓前后端，不保双轨。

5. **警报面**（D1）：
   - 删 supply_block 前瞻（D7 删 auto_supply 供给守卫的配套）—— live 面换
     `supply_capped`：已卡人口**且**队列/在途没排供给建筑才报（排了就闭嘴），
     建议带 before_uid；干跑面 from_curve 同 kind；
   - skipped 项进警报：prereq_missing 家族用 `_ever_ready` 判「曾有现无
     （被摧毁，error）/从没建（warn + 在 uid 前插建造项）」；一次性
     （同一 uid 只报一次，状态不会自己变回去）；
   - capacity 等待：info 起步，超 60s 升 warn（不升 error —— 瞬态）。

## 被取代的拍板

- **S11 队首门控冻结整队**：只对 pending 保留；skip 不再冻结。
- **rev 4 的「队列里不可能出现已发出/在途」**：账本化后在途项就在队列里
  （in_progress）。
- **B2 的 index 语义**（insert 按剩余队列位置）：uid 语义取代；「插入只具
  后效性」的帧边界保证不变。

## 权衡与后果

- 队列快照变长（含历史）：observe 折叠已完成/已跳过为计数；audit_queue 只看
  未执行项；前端表格按 status 渲染。真机一条队列几十项，不是问题。
- uid 是会话内标识，不落规划文件（规划是 authoring 数据，uid 是执行轨迹）；
  `ops_to_items` 产物无 uid，入队时分配 —— 批 3 仿真表把 uid 穿透 Op 后再议。
- 拒绝 `not_reached`（agent 文档提议）：仿真 horizon 截断处 pending 即可，
  多一个状态只多一种解释成本（用户拍板 D8）。
