# 模块审查 + 端到端可行性（review node 2026-08-19）

> 节点目标：能根据写好的 flow 跑真实游戏 + 执行战术。
> 结论：**战斗 flow 端到端通**（真机验过）；**bio_push 全链跑不了**——缺**生产运行时**那半边。

## 1. 端到端可行性（真机）

### ✅ 通的（战斗 flow）
- `run_flow_slice.py`（scv_move）：driver→world→flow→driver 真 SC2，SCV 移到目标（dist 单调降）。
- `run_flow_arrived.py`（本节点）：formup(group_count)→advance(move)→**arrived(空间谓词)→exit**，真 SC2，SCV 走到 [50,50] dist 0.5→arrived→exit。**空间谓词端到端验通。**
- `run_driver_check.py`：抽 RawGameState + 发 move → state 反映。

→ **flow→SC2 管道 + 战斗引擎（含空间谓词）端到端通**。

### ❌ 跑不了的（bio_push 全链）
bio_push 要**枪兵+运输机**，得**造兵营+训练**。而**生产运行时没建**（只有 QueueItem 类型 + catalog）→ formup `group_count>=6` 永远等不到枪兵 → 卡死在 formup。

### 错位判断
不是"放错地方"，是"**缺半边**"：战斗半边（driver/world/flow/tactical_map）建好+验通；**生产半边（生产运行时+constraint+mechanics+catalog data+WorkerAllocator）没建**。driver 的 TRANSLATORS 已能分派 build/train，但**没人发**（没生产运行时）；game 有 catalog(ops) 但**没 catalog data**（稳定 ID 映射）。

## 3. 跑通 bio_push 端到端要补的（优先级）

1. **catalog data**（`game`）：`terran.json`（单位/建筑数据）+ 稳定 type ID↔burnysc2 `UnitTypeId`/`AbilityId` 映射。**地基**——build/train 的 type 才能映射。
2. **mechanics**：三族规则（造价/建造时间/前置）。constraint + 生产门控要用。
3. **constraint**：可行性校验（矿/供给/前置/放置/重叠）。生产 queue 门控。
4. **生产运行时**（新组件，归 engine 层）：drain `QueueItem` 队列 → 查 constraint 可行 → 发 build/train/research `Operation` → driver 应用。**这是 bio_push 拿到枪兵的关键**。
5. **WorkerAllocator**：`assign_workers`（SCV 矿/气/空闲自动分配，饱和上限+溢出 idle）→ 采够矿才能造。

补完这 5 块，bio_push 才能真跑：生产造兵营+训练枪兵→进 free 池→group 补兵→formup 满员→advance/combat/retreat（战斗半边已通）。
