# sc2_agent_next 需求文档 v0.1（场景 / 应对 / 边界）

> 状态：v0.1，架构级 + 待定决策点清单。细节随实现补全。
> 本文档取代 `docs（旧）/` 中与下列内容冲突的部分（尤其"V1 只 Terran""M0→M9 线性""compiler/runtime/driver 三层""Intent 命名"）。
> 来源：grill-me 会话确认的架构共识（2026-08）。

## 0. 范围与原则

- V1 = **三族全实现、不留技术债** + 全量 UI（端到端）。
- 搭建方式：**渐进分层**，不一次铺开；以 **flow 系统为第一步**（先游戏接口 + 离线手写 flow 验证操作可实现）。
- 不留技术债的两条设计预留：
  1. **分配走 `Allocator` 接口**：V1 给 FCFS + sticky lease 简实现，日后升级 spec-006 全套仲裁只换实现，不动引擎。
  2. **状态分骨架/派生**：group/strategy 状态从第一天就分"骨架"（active_step、leased_units、variables）与"派生"（counts、center、距离）；V1 即使不做 recovery，这个分离是日后启用 recovery 的前提，几乎零成本，retrofit 很贵。

### 红线（任何时候不得回退）

| ID | 红线 |
|---|---|
| R1 | flow（引擎）不知具体单位（unit_tag）；只在 `(group, stable_type)` 抽象上操作 |
| R2 | driver 零业务规则（不计算 power/addon，不认识 group/slot/Strategy） |
| R3 | 用户操作优先于 flow；user_leased 单位不可被 group 分配 |
| R4 | 不模拟战斗结果；combat 不进 planner |
| R5 | live 中不能创建/编辑模块与 Strategy |
| R6 | 任何 flow（combat Strategy/assembly）提交必须 validate + compile；生产队列 op 轻量，执行时按 constraint 可行性门控（不绕过） |
| R7 | 配置错误可降级告警，不崩游戏 |
| R8 | 旧观察不得作为当前行动依据 |

## 1. 模块划分与依赖（已锁定）

| 模块 | 职责 | 有状态 | 依赖 |
|---|---|---|---|
| **driver** | 连 SC2；收 operate、返 **RawGameState**（SC2 原生，尽量不转换）| 源/汇 | game |
| **game** | catalog（单位/建筑/能力 + zh 名）+ RawGameState/GameState 类型 + stable type ID | 无 | — |
| **world** | `RawGameState → GameState`（坐标/网格转换 + 规则层 via mechanics.LayerComputer，D11 启用）| 无 | game、mechanics、map |
| **flow（引擎）** | load .md → 每帧执行 Step 分支 + 生产 policy → 输出 operate；内含 group/free池/lease + `(group_slot,type)→unit` 展开 + 去重 | **有**（active_step、group lease、variables） | constraint、map、game |
| **constraint** | `(GameState, action)→bool`：晶体矿/瓦斯/供给/前置/放置/重叠 | 无 | game、mechanics、map |
| **planner** | `(GameState, production_sequence)→投影曲线`；逐帧/逐秒顺序模拟 | 无 | constraint、mechanics、game；**不依赖 flow 运行期** |
| **map** | 点位名↔坐标登记 + 空间查询原语（distance/center/nearest/region） | 无 | game |
| **mechanics** | 三族规则：造价/建造时间/前置/LayerComputer（power/addon） | 无 | game |

数据流：
```
driver ──RawGameState(SC2原生)──▶ world ──GameState(我们的格式+规则层)──▶ flow(引擎,有状态) ──operate──▶ driver
                              │ 调用谓词/可行性
            ┌─────────┬───────┼──────┬────────┐
            ▼         ▼       ▼      ▼
        constraint  map    game  mechanics
            │
            └──▶ planner(无状态,不依赖 flow 运行期)
```

## 2. 命名与接口契约

- **状态两面**：driver 出 `RawGameState`（SC2 原生）；`world` 模块转成 `GameState`（我们的坐标/网格 + 规则层，D11 启用）给 flow 消费。
- **driver 边界动作对象**：`Operation`（docs 原名 Intent，已改）。字段 `(op_id, unit_tags, action, params, seq)`。
- **flow 分支内部动作**：`group_action` do 项，字段 `(group_slot, type, action_atom, params)`；`type` 是两段式 stable id（如 `terran/marine`，T1 词汇统一）。
- flow 的 `group_action`（group 级）→ 引擎内部展开 `(group_slot,type)→unit_tags` → `Operation`（unit 级）→ driver（原 `ActionRequest` 中间类无人实例化，已删；展开步合入引擎）。
- `OperationSinkPort`（docs 原名 IntentSinkPort）：flow 定义、引擎实现，收 group 级动作、出 `Operation`。
- `GamePort`（driver 实现）：`start / stop`、`submit_operations(ops)→ApplyResult`、`events(cursor)→[GameEvent]`、`read()`（仅离线/单测）。
- `RuntimeSink`（引擎实现、driver 推）：`on_game_state(RawGameState)`、`on_session_event`。
- Operation 下一 step 生效（当前 step 不生效）；Observation 以游戏时间整秒边界生成。

> 待定：`ApplyResult` 字段（D6）、`GameEvent` 目录（D7）、driver 是否暴露 SC2 `game_data`（D8）。

## 3. 场景 / 应对 / 边界（架构级）

### S1 实时对局每帧求值
- **场景**：driver 每 step 推 RawGameState；world 转 GameState；flow 引擎每帧消费 GameState。
- **应对**：走 active step 的 branches → 测 `when` → 命中分支 `do` 产 `group_action` → 去重 → 展开 `(group_slot,type)→unit_tags` → `Operation` → `submit_operations`；下一 step 生效。
- **边界**：flow 不知具体单位（R1）；driver 零规则（R2）；Operation 下一 step 生效；旧观察不作当前依据（R8）。

### S2 多策略并行竞争单位
- **场景**：两个 group 抢同一 free 单位。
- **应对**：`Allocator` 仲裁（V1 = FCFS + sticky lease）。
- **边界**：V1 不做 spec-006 全套（pool_key/share/两阶段）；走 `Allocator` 接口，冲突多了再升级实现，不动引擎。

### S3 单位死亡 / 自动补兵
- **场景**：group 内兵死亡，或生产产出新兵进 free 池。
- **应对**：group auto-refill 滞回：数量在 `[min, target)` 不补，跌破 `min` 才补回 `target`，`max` 为硬上限；`min` 省略 = 跌破 target 就补，`min: 0` = 只在空组时补（T3/D6 + H2）。turnover 对 flow 透明（flow 只看 `group_count`）。
- **边界**：补兵只从 free 池取，不抢 `user_leased` / 其他 group lease（R3）。

### S4 生产可行性判断
- **场景**：要不要 train/build/research。
- **应对**：`constraint (GameState, action)→bool`（晶体矿/瓦斯/供给/前置/放置/重叠）。
- **边界**：只判当前可做性，不模拟未来；不依赖 SC2。

### S5 生产投影
- **场景**：看未来资源/单位曲线（UI/agent/alerts）。
- **应对**：`planner (GameState, 队列)→curve`，逐帧/逐秒顺序模拟队列消费（可行性门控），用 constraint+mechanics。
- **边界**：不依赖 flow 运行期；不模拟战斗（R4）；planner 是唯一预测源。

### S6 用户接管单位
- **场景**：用户手动操作某 group 内单位。
- **应对**：单位即离 group（记 `group_user_takeover`）；group 通过 `group_count` 分支决定等待/换 step/失败。
- **边界**：用户优先于 flow（R3），不抢回；剩余行为符合 `group_count` 分支。

### S7 崩溃恢复
- **场景**：引擎/driver 崩。
- **应对**：V1 延后自动恢复（崩了重开游戏，保留计划数据）；但状态分骨架/派生从第一天设计。
- **边界**：V1 不做自动恢复；状态分离是日后启用 recovery 的前提。

### S8 flow 提交变更（combat 部分）
- **场景**：改 combat assembly / 参数 / 绑定（Strategy/group）。
- **应对**：`validate + compile`；hot 参数保留、结构参数重置该实例。
- **边界**：live 不能创建新模块/Strategy（R5）；不绕过校验（R6）。生产队列不在 flow 提交范畴——生产用工具 op（`append/prepend/clear`）直接改队列，执行时按 constraint 可行性门控，不需 validate/simulate。

### S9 空间查询 / 点位
- **场景**：Step 谓词要 `distance/region/group_center`，或解析点位名。
- **应对**：map 提供空间查询原语 + 点位名↔坐标登记。
- **边界**：V1 手工登记点位；自动划分矿区后置。

### S10 driver 连 SC2
- **场景**：启动游戏、收 op、推 RawGameState、推事件。
- **应对**：driver `GamePort(start/stop/submit_operations/events)`；推模型 + 游戏时间整秒观察。
- **边界**：driver 不写业务规则、只填 raw 动态层（creep/visibility）（R2）。

### S11 生产队列（runtime）
- **场景**：执行/调整生产计划（建造/训练/worker 分配）。
- **应对**：纯线性队列 + 工具 op（`submit_queue/append/prepend/clear/remove/reorder`，inline 参数）；队首按 constraint 可行性门控；`assign_workers` 自动分配 SCV（饱和+溢出转 idle）。
- **边界**：无 stage/policy/连续维持规则（post-V1 再加）；生产不进 flow validate/compile（R6）。

## 5. 实现顺序（flow-first 渐进）

```
P0  钉影响边界（设计）：GameState 字段 + operate 原子目录 + 一份样例 Flow/Strategy
P1  driver spike：连 SC2，拿真实 RawGameState + 验 operate 执行（用临时类型，结论回流 P2）
P2  game + world：catalog + RawGameState/GameState 类型 + stable type ID（三族 schema）；world 做 RawGameState→GameState 转换（V1 仅坐标/网格，LayerComputer 待 D11）
P3  flow 引擎最小：load .md + 纯战斗 step 执行 + 展开 + 去重（谓词先用纯 GameState 类：group_count/game_time）
P4  constraint + map 空间原语：补全谓词（arrived/distance/has_building/enemy_count_near）
P5  生产 policy + planner：生产执行 + 投影
P6  mechanics 三族规则（造价/时间/前置；LayerComputer 待 D11）
P7  agent / api / browser
```
每步退出门禁：contract test + 场景测试 + import 检查（依赖方向锁死）。

## 6. 性能基线（SOFT，spike 后回填）

| 项 | 基线 |
|---|---|
| 单 step 每帧求值 + 去重 | < 2 ms |
| Allocator 同帧 100 请求 / 1000 单位 | < 50 ms |
| ObservationPacket 生成（1s 节拍） | 不阻塞下一 GameState |
