# P0 影响边界（flow 引擎的输入面 × 输出面）

> 状态：v0.3，钉 D1/D2/D3 + 生产模块安排 + RawGameState/GameState 两段。实现中精修。
> 目的：定义 flow 引擎的**输入面**（GameState 字段）× **输出面**（operate 原子目录），并用一份带复杂 Step 的 Flow/Strategy 样例验证边界够不够用。
> 关联：`docs/需求文档-v0.1.md` §4 D1/D2/D3。

## D1 — 状态两面：RawGameState（driver 原生）→ world 模块 → GameState（处理后）

driver 只提供**原生 raw**；**world 模块**把 RawGameState 处理成 flow 等消费的 **GameState**（我们的坐标/网格约定 + 规则层）。driver 因此保持"纯读 SC2 + 原生打包"，不做坐标转换、不做规则计算。

```yaml
RawGameState:               # driver 输出，SC2 原生，尽量不转换
  seq: int
  game_time: float
  resources: { minerals: int, vespene: int, supply_used: int, supply_cap: int, larva?: int }   # larva Zerg 预留
  units: list[RawUnit]       # 见下；position/creep grid 为 SC2 原生形态
  map_layers_raw: { creep: grid, visibility: grid }

RawUnit:
  tag, type, owner, position(SC2原生), facing, hp, hp_max, shield, energy,
  build_progress, orders(list[Order]), cargo(list[tag]), buffs(list[str])
  # orders: ability / target_tag / target_pos

GameState:                  # world 模块输出，flow/constraint/planner 消费
  = RawGameState 经 world 处理：
    - position → 左下原点浮点（SC2 原生不同则转换；P1 spike 确认 SC2 原生形态）
    - creep/visibility grid → 按 map grid 朝向/分辨率对齐
    - power / addon_attachment 层 → mechanics.LayerComputer 补（D11 启用；V1 不补，接口预留）
  # 其余字段同 RawGameState
```

### world 模块

- **职责**：`RawGameState → GameState`（坐标/网格转换 + 规则层补充）。
- **依赖**：game（类型）、mechanics（LayerComputer，D11 启用）、map（grid/region 对齐）。
- **不做**：不读 SC2（driver 干）、不决策（flow 干）、不模拟未来（planner 干）。
- **V1**：只做坐标/网格转换（规则层 D11 后补，接口已预留 → 不算技术债）。
- **定位**：driver 与 flow 之间的处理层。模块表新增一行（见需求文档 §1）。

### 数据流

```
driver ──RawGameState(SC2原生)──▶ world ──GameState(我们的格式+规则层)──▶ flow(引擎,有状态)
                                       │ 依赖 mechanics(LayerComputer) + map(grid)
flow ──Operation──▶ driver
```

### GameState 不携带

group/strategy 内部状态（引擎骨架+派生）；事件流（走 driver `events()` 通道，引擎 ingest；`event_occurred` 查引擎内事件流）；未来预测（planner 输出）。注：V1 不含规则层（power/addon），D11 后补。

### 谓词 → 字段覆盖检查（验证 D1 够不够；谓词消费的是 GameState）

| 谓词（spec-003 §4.1） | 依赖 GameState 字段 |
|---|---|
| group_count(group_slot[, type]) | units（按 group lease 过滤）|
| arrived(group_slot, target_position, r) | units.position |
| distance_between(a, b) | units.position |
| group_center_in_region | units.position + region（map 模块）|
| group_hp_ratio | units.hp / hp_max |
| engaged / under_attack | units.orders + hp 历史引擎推导 |
| enemy_count_near(anchor, r) | units(owner=enemy, visible) + position |
| enemy_visible_in(region) | units(owner=enemy) + region |
| has_building(type[, region, ready]) | units(type, build_progress) |
| has_ready_base(region) | units(type, build_progress) |
| unit_count(type) | units(type, owner) |
| game_time / strategy_elapsed / step_elapsed | game_time + 引擎状态 |
| timer_elapsed(name) | 引擎状态（timer deadline）|
| event_occurred(...) | 引擎事件流（非 GameState）|
| user_cancel | 引擎状态 |

→ 结论：D1 字段覆盖所有 V1 谓词；`engaged`/`under_attack`/`user_cancel` 靠引擎从 `units.orders` + hp 历史推导，不额外加字段。

## D2 — operate 原子目录（flow 引擎的输出面）

flow 引擎产出 operate（战斗 Step `do` + 生产 policy 都产）。driver 边界 `Operation.action` 取值即下表。原子目录**只增不改**。参数名类型显式；slot 参数统一叫 `group_slot`。

### 战斗 action 原子（Step `do` 用，粒度 = (group_slot, stable_type)）

| action | 签名 | position/target 类型 |
|---|---|---|
| move_to | move_to(position) | point / region / group_center(group_slot) |
| attack_move_to | attack_move_to(position) | point / region |
| hold_position | hold_position(position=null) | point / null |
| follow | follow(group_slot, type?) | group_slot + type |
| focus_fire | focus_fire(target_unit) | unit_tag（解析后）/ nearest_enemy |
| load | load(transport_group_slot) | group_slot |
| unload | unload(position) | point / region |
| use_ability | use_ability(ability, target_position=null, target_unit=null) | ability_id + point/unit_tag |
| patrol | patrol(positions) | list[point] |
| stop | stop() | — |

### 生产 action 原子（生产队列项用）

| action | 签名 | 说明 |
|---|---|---|
| build | build(type, position) | 建造；position = point/region/placement_policy（D4）|
| train | train(type) | 训练；展开到具体 producing building 的 unit_tag |
| research | research(ability) | 升级 |
| cancel | cancel(order) | 取消建造/训练 |
| assign_workers | assign_workers(task, count) | SCV 矿/气/空闲自动分配；engine 挑 SCV+矿脉/气井，饱和上限+溢出转 idle |
| # morph | morph(type) | Zerg 预留（三族无债）|

### target 解析类型

| 类型 | 来源 |
|---|---|
| point | 字面坐标 `[x,y]` 或 map 点位名（查表）|
| region | map 注册的区域名（含中心/范围）|
| group_center(group_slot) | 引擎从 group leased units 算中心 |
| nearest_enemy | 引擎从可见敌方 units 取最近 |
| unit_tag | focus_fire 的具体目标（driver 级）|

## D3 — 样例 Flow.md + Strategy.md（带复杂 Step）

验证 D1×D2 边界。场景：**两船兵前压**（速开二矿 → 两船兵生产 → 前压）。

> 语法：YAML 结构。`when` 是分支关键字，**语义 = if/elif/else**（有序、首条命中、末条无 `when`=else）。

### Flow.md（FlowAssembly）

```yaml
assembly_schema_version: 1
id: tvp_2medivac_push
race: terran

production_sequence:
  - instance_id: m0
    module_ref: fast_expand
    version: 1
    params: { expand_after: after_barracks }
  - instance_id: m1
    module_ref: two_medivac_production
    version: 1
    params: { marine_target: 16, medivac_target: 2 }

groups:
  - group_id: G1
    name: 前压主力
    composition:
      terran/marine:   { min: 12, target: 16, max: 16 }
      terran/medivac:  { min: 1,  target: 2,  max: 2  }
    assemble_at: { kind: region, ref: main_base }
    refill_anchor: group_center
    replenish: { enabled: true, check_every_seconds: 10 }
    allocation: { pool_key: army_ground, share: 100, priority: strategy }

strategy_instances:
  - instance_id: s1
    strategy_ref: bio_push
    version: 1
    bindings: { main: G1 }
    params:
      target_region: enemy_natural
      min_marines: 12
      min_medivacs: 1
      max_gap: 6
```

### Strategy.md（bio_push，含复杂 Step `advance`）

```yaml
manifest_version: 1
id: bio_push
version: 1
race: [terran]

display_name_zh: 两船兵前压
description_zh: 运输机达标后的正面推进
boundaries_zh: 不负责生产；不处理 user_leased 单位

group_slots:
  - { name: main, display_name_zh: 主战部队 }

params:
  target_region: { type: region, live_editable: false }
  min_marines:   { type: int, default: 12, live_editable: true }
  min_medivacs:  { type: int, default: 1,  live_editable: true }
  max_gap:       { type: int, default: 6,  live_editable: true }

variables:
  checkpoint: { type: point, default: null }

initial_step: formup

steps:
  - step_id: formup
    branches:
      - when: group_count(main) == 0
        do: [ exit_strategy(kind=failed, reason=GROUP_EMPTY) ]
      - when: group_count(main, terran/marine) >= params.min_marines
              and group_count(main, terran/medivac) >= params.min_medivacs
        do: [ exit_step(kind=done, reason=FORMED) ]
      # else: 等待，不发命令

  - step_id: advance                  # ← 复杂 Step
    locals: [ mode ]                  # 进入时重置
    progress: { metric: distance_to_target, label_zh: 距目标距离 }
    branches:
      - branch_id: b_arrive
        when: arrived(main, region_center(params.target_region), 5)
        do: [ exit_step(kind=done, reason=ARRIVED) ]

      - branch_id: b_ambush
        when: enemy_count_near(group_center(main), 15) > 8
        do: [ exit_step(kind=interrupted, reason=AMBUSHED) ]

      - branch_id: b_low_hp           # 血量过低：存档 + 失败退出
        when: group_hp_ratio(main) < 0.4
        do:
          - set_variable(name=checkpoint, value=group_center(main))
          - exit_step(kind=failed, reason=UNITS_LOST)

      - branch_id: b_default          # else：推进 + 运输机跟随（同 slot 多兵种协同）
        do:
          - group_action(group_slot=main, type=terran/marine, action=attack_move_to,
                         params={ position: region_center(params.target_region) })
          - group_action(group_slot=main, type=terran/medivac, action=follow,
                         params={ group_slot: main, type: terran/marine })

  - step_id: combat
    branches:
      - when: enemy_count_near(group_center(main), 12) == 0
        do: [ exit_step(kind=done, reason=ENEMY_CLEARED) ]
      - when: group_count(main, terran/marine) < 6
        do: [ exit_step(kind=failed, reason=UNITS_LOST) ]
      - # else: 集火最近敌
        do:
          - group_action(group_slot=main, type=terran/marine, action=focus_fire,
                         params={ target_unit: nearest_enemy })

  - step_id: retreat
    branches:
      - when: arrived(main, region_center(main_base), 8)
        do: [ exit_step(kind=done, reason=SAFE) ]
      - # else
        do:
          - group_action(group_slot=main, type=terran/marine, action=move_to,
                         params={ position: region_center(main_base) })
          - group_action(group_slot=main, type=terran/medivac, action=follow,
                         params={ group_slot: main, type: terran/marine })

  - step_id: hold
    branches:
      - do: [ exit_strategy(kind=done, reason=SAFE) ]

edges:
  - { from: formup,  to: advance, kind: done,        reason: FORMED }
  - { from: advance, to: combat,  kind: interrupted, reason: AMBUSHED }
  - { from: combat,  to: advance, kind: done,        reason: ENEMY_CLEARED, max_iterations: 20 }   # 环
  - { from: advance, to: retreat, kind: failed,      reason: UNITS_LOST }
  - { from: combat,  to: retreat, kind: failed,      reason: UNITS_LOST }
  - { from: retreat, to: hold,    kind: done,        reason: SAFE }

loop_limits: { max_step_transitions: 100 }
tests:
  - scenario: bio_push_ambush_v1
```

### 边界验证结论

样例 `advance` Step 用到的：谓词 `arrived` / `enemy_count_near` / `group_hp_ratio` + 空间工具 `group_center` / `region_center` + 动作 `attack_move_to` / `follow` + 可写 `set_variable` + `exit_step`（done/interrupted/failed）+ 环回边（combat→advance）+ 同 group_slot 多兵种协同（marine 推进 + medivac 跟随）。**全部落在 D1 字段 × D2 原子目录内**，无需新增字段/原子 → 边界够用。

## 生产模块安排（纯线性队列 + 工具操作，无 stage/policy/维持规则）

生产 = **运行时线性 `build/train/research/assign_workers` 队列**，按序消费，队首按 constraint 可行性门控（`assign_workers` 立即发、无资源门控）。**无 stage、无 policy、无连续维持规则**（post-V1 再加）。队列项 = D2 的生产 operate。

### 队列项 schema

```
QueueItem:
  op: build | train | research | cancel | assign_workers
  type: stable_type_id              # build/train/research 用
  count: int = 1                    # ≥1，默认 1
  position: point|region|placement_policy   # build 用（D4）
  task: mineral|gas|idle            # assign_workers 用
  when: condition?                  # 可选一次性触发条件（如 supply≥N 才发）
Queue: { name: str, items: [QueueItem] }
```

### 工具操作（live agent，inline 参数）

| op | 语义 |
|---|---|
| submit_queue(name, items) | 创建/替换命名队列并启动（inline items）|
| append(name, items) | 队尾加 |
| prepend(name, items) | 队首插（紧急 / LLM 临时决策）|
| clear(name) | 清空 |
| remove(name, ref) / reorder(name, refs) | 删 / 重排 |

- live agent 用 **inline 参数**（no_think = 结构化 patch，一次调用）。
- 离线预编排用**文档**（人写命名队列文件，加载注册）；live agent 可引用已注册队列名，或 inline 提交新队列。

### SCV 矿↔气↔空闲（assign_workers）

- `assign_workers(task, count)`：task = `mineral | gas | idle`。
- **自动分配**：engine 的 WorkerAllocator 从 worker 池挑具体 SCV + 具体矿脉/气井；agent 只给意图。
- **避免满采**：每矿脉/气井有饱和上限（矿 ~2、气井 ~3），engine 不超配。
- **满采自动转空闲**：超出饱和的 SCV 自动落 idle。
- 队列项形式（按序发，发后 quota 持续生效，直到下条 assign_workers 改）：如 `[build refinery, assign_workers(gas, 3), build factory]`。
- `idle` = 把 SCV 从矿/气解放（给建造/修理用）。

### 生产与战斗的衔接（无 signals）

group auto-refill 从 free 池取兵；free 池由生产队列的 `train` 项填充。strategy 首步 `group_count` 等待。无需 signals。

### post-V1 再加的（不影响 V1）

- 连续维持规则（sustained-combat 补兵 / harassment 替换 worker）。
- `active_when`、条件表达式参数等。

## 已确认 / 待确认

**已确认：**
- .md 语法 = YAML + `when`（语义 = if/elif/else）。
- slot 参数统一叫 `group_slot`。
- **生产 = 纯线性队列 + 工具操作**（`submit_queue/append/prepend/clear/remove/reorder`，inline 参数），无 stage/policy/维持规则；队列项 `count≥1` 默认 1；`assign_workers(task,count)` 自动分配 SCV 矿/气/空闲（饱和上限+溢出转 idle）。
- live agent 用 inline 工具参数；离线预编排用文档注册命名队列。
- 生产 `build/train/research/assign_workers` 算 operate（driver 边界 `Operation`）。
- GameState 带 `orders`；`engaged`/`under_attack`/`user_cancel` 靠引擎推导。
- 样例复杂度够用。
- **状态两面**：driver 出 `RawGameState`（SC2 原生）→ `world` 转 `GameState`（我们的坐标/网格 + 规则层，D11 启用）；driver 保持纯读原生。

**待办：**
1. **world 模块**：V1 只做坐标/网格转换；D11 插 mechanics.LayerComputer（power/addon）。
2. **placement policy 目录**（D4）：`build` 的 position 怎么定，留 P5。
3. **post-V1**：连续维持规则（补兵/替换 worker）、`active_when`、条件表达式参数。
